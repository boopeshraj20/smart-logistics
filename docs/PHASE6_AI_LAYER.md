# Phase 6 — AI Intelligence Layer

Status: **delivered.** scikit-learn models for demand forecasting, predictive
maintenance, AI vehicle assignment and green logistics, with explainable AI on
every prediction and live frontend wiring (dashboard + `/ai/demand` +
`/ai/sustainability`).

## Models

| Model       | Target                                     | Algorithm                  | R²    | MAE        |
| ----------- | ------------------------------------------ | -------------------------- | ----- | ---------- |
| **demand**  | Daily shipments (14-day forecast)          | `GradientBoostingRegressor` | 0.75  | 2.6 / day  |
| **health**  | Fleet health score (0–100)                 | `Ridge`                     | 0.82  | 2.7 pts    |
| **service** | Accumulated service-earning factor (₹)     | `ElasticNet`                | ~1.00 | ~0.004     |
| **assignment** | ML dispatch utility per vehicle        | `LinearRegression`          | 0.91  | 0.04       |
| **fuel**    | Litres burned per trip                     | `Ridge`                     | 0.87  | 10.4 L     |

- `service` is deliberately trivial to fit — it is a deterministic accrual law
  treated as a learned "earning curve" demonstration.
- Assignment applies a hard feasibility penalty (×0.1) when capacity or
  availability fails, then orders by predicted utility.
- `demand` uses a **chronological holdout** (last 14% of the 730-day series) so
  the evaluation is honest about time-series performance.

## Datasets (deterministic, no hardware/IoT)

Generated by seeded PRNGs in `backend/app/ml/datasets.py`, exported to
`backend/data/raw/*.csv`. Signals replicate public-dataset patterns:

- **demand.csv** (730 rows) — weekday lift, Diwali/Pongal/Durga Puja festival
  windows, monsoon dip, growth trend, annual seasonality, event noise.
- **maintenance.csv** (120 rows) — per class interval/mileage/capacity/speed,
  health formula `98 − km_since·0.00055 − age·0.09 − utilization pressure`.
- **assignments.csv** (2,400 rows) — label *derived* from features via a
  cost-first policy (0.40 cost + 0.20 fuel + 0.15 available + 0.15 health +
  0.10 capacity fit) so the regressor learns a defensible policy.
- **fuel.csv** (3,000 rows) — `fuel = (distance / mileage) × (1 + 0.25 load_ratio)`.

## Feature engineering (`backend/app/ml/features.py`)

- **Demand (7):** trend, weekday, is_weekend, monsoon, festival window,
  rolling-7 mean, lag-7. Target `shipments`.
- **Maintenance (6):** km_since_service, odometer, interval, age, type_code,
  avg_daily_km. Targets: `health_score` / `service_earnings`.
- **Assignment (9):** cost/km, mileage, CO₂/km, fuel/km, availability,
  health, capacity fit, utilization, fleet size.
- **Fuel (5):** distance, weight, load ratio, type code, mileage.
- Constants: `CO2_PER_LITRE = 2.68` kg/L (diesel).

## Explainability contract

Every prediction returns an `explanation`:
`confidence` (0–1 from residual spread), `summary`, human-readable `bullets`,
and up to 5 `factors` as `{feature, value, contribution, direction, note}`.
For linear models contributions are signed `(x − mean) × coef`; the demand
model reports feature importances. Fleet/eco/assignment explanations are
written in policy language (e.g. "Operating cost per km: contribution −0.124
vs fleet average").

## API endpoints

## How to test it

Backend (training + offline smoke):

```powershell
cd backend
py -m app.ml.models                 # trains 5 models, prints metrics, forecast, health, assign, eco
```

Backend API (interactive):

```powershell
cd backend
py -m uvicorn app.main:app --reload --port 8000
# open http://127.0.0.1:8000/docs
```

Frontend (dev against the live API):

```powershell
cd frontend
npm run dev
# dashboard → AI Insights (/ai/demand), Sustainability (/ai/sustainability)
```

Quick API checks:

```powershell
curl http://127.0.0.1:8000/api/v1/models
curl "http://127.0.0.1:8000/api/v1/forecast/demand?days=7"
```

Resilience: stop the backend and reload the UI — forecast/health/eco panels
fall back to deterministic client-side estimates (`src/services/ai.ts`) and
show a "Local estimate"/"Backend offline" state instead of breaking.
